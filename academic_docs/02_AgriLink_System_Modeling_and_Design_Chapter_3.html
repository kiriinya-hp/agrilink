1. High-Level System Architecture

AgriLink adopts a Three-Tier Service Architecture designed to separate presentation, business logic, and transactional data persistence. This ensures scalability, security of financial transactions, and responsive client interactions across mobile and desktop devices.

2.2 Critical Use Case Specifications

#### Use Case UC-04 & UC-05: Create Order & Fund Escrow * Primary Actor: Commercial Buyer * Pre-condition: Buyer is authenticated and has verified KYC status. Produce listing is active and available in requested quantity. * Main Flow: 1. Buyer selects produce listing, specifies quantity (kg/tonnes), and target delivery date/location. 2. System calculates total order cost = $(Quantity \times Unit Price) + Estimated Transport Fee + Platform Fee$. 3. System prompts Buyer to initiate escrow deposit via Mobile Money or Card. 4. Payment Gateway processes transaction; sends callback webhook to AgriLink. 5. System creates an ESCROW_HOLD transaction and transitions Order status to ESCROW_FUNDED. 6. Farmer receives an automated SMS and in-app notification of the funded order. * Post-condition: Funds are secured in escrow; inventory quantity is reserved.

#### Use Case UC-08 & UC-09: Inspect Delivery & Release Escrow * Primary Actor: Commercial Buyer & Farmer * Pre-condition: Transporter marks status as ARRIVED_AT_DESTINATION. * Main Flow: 1. Buyer inspects received produce against agreed grade and weight specifications. 2. Buyer enters delivery confirmation OTP or signs off digitally on the platform. 3. System transitions Order state to COMPLETED. 4. Escrow module automatically triggers payout:

  • Net Produce Amount $\rightarrow$ Disbursed to Farmer's registered wallet.
  • Transport Fee $\rightarrow$ Disbursed to Transporter's wallet.
  • Platform Commission $\rightarrow$ Credited to AgriLink revenue account.
    • 5. Both parties receive settlement receipts via SMS/Email.
